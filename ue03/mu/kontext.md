# Stakeholder und Systemkontext — Terminplaner für die THM

## Stakeholder

| Stakeholder | Worauf hat er Einfluss? |
|---|---|
| Studierende | Sie haben die Möglichkeit, freie Termine im System zu buchen. |
| Lehrende | Sie legen entsprechende Sprechstunden fest, die dann gebucht werden können. |
| Mitarbeiter im Sekreteriat | Sie haben so einen Überblick über alle Termin und helfen bei der Organisation.|
| Rechenzentrum | Das Rechenzentrum stellt das Hochschulkonto bereit, über welches sich alle anmelden, und soll das System später betreiben. |
| Datenschutzbeauftragte Person | Sie achtet darauf, dass die persönlichen Daten geschützt bleiben. |
| Entwicklerteam | Sorgt dafür, dass die Anforderungen an das System korrekt umgesetzt werden. | 

## Systemkontext

| Aspekt | Art | Warum gehört er zum Kontext? |
|---|---|---|
| Studierende | Person | Sie nutzen den Terminplaner und können somit freie Termine buchen und das System verwenden. |
| Hochschulanmeldesystem | System im Betrieb | Der Terminplaner muss die Anmeldung über das Hochschulportal ermöglichen. |
| Beginn des Semesters | Ereignis | Zu Semesterbeginn müssen die neuen Termine aktualisiert werden. |
| KI-Agent | System im Betrieb | Er kann über die API AKtionen ausführen, wie z.B nach freien Sprechstunden suchen. |
| iCal-Datei | Dokument | Die Datei enthält Termininformationen und kann heruntergeladen werden. |

## Irrelevante Umgebung

- Notensystem im E-Campus — Das System der Notenverwaltung läuft über E-Campus und hat nichts mit der Terminplanung zu tun.
- Mensa der THM — Auch die Planung des Speiseplans und die gesamte Essenssituation hat keinerlei Auswirkungen auf die Terminplanung.
