# Stakeholder und Systemkontext — Terminplaner für die THM





## Stakeholder



| Stakeholder | Worauf hat er Einfluss? |
|---|---|
| Dozenten | Sie legen fest, wann und wie lange sie Sprechstunden-Termine anbieten. |
| Studierende | Sie wollen schnell einen freien Termin finden und ihn auch wieder absagen können. |
| Rechenzentrum der THM | Es betreibt die Server und sorgt dafür, dass man sich mit dem THM-Login anmelden kann. |
| Datenschutzbeauftragte der THM | Sie legt fest, welche Daten gespeichert werden dürfen und wann sie gelöscht werden müssen. |
| Sekretariate | Sie wollen Termine auch für Lehrende eintragen oder ändern können. |
| Hochschulleitung | Sie entscheidet, ob der Terminplaner eingeführt wird und welche Regeln für alle gelten. |


## Systemkontext




| THM-Login | System im Betrieb | Der Terminplaner muss die Anmeldung darüber laufen lassen, verwaltet die Konten aber nicht selbst. |
| E-Mail-System der THM | System im Betrieb | Über die E-Mail werden Bestätigungen und Absagen verschickt. |
| Kalender der Lehrenden  | System im Betrieb | Termine sollten im Kalender auftauchen, damit es keine Überschneidungen gibt. |
| Semesterbeginn und Prüfungszeit | Ereignis | In diesen Zeiten werden viel mehr Termine gebucht, darauf muss das System vorbereitet sein. |
| Krankheit oder kurzfristige Absage | Ereignis | Wenn ein Termin ausfällt, müssen die gebuchten Studierenden informiert werden. |
| Datenschutzordnung der THM | Dokument | Sie gibt vor, wie mit den gespeicherten Daten umgegangen werden muss. |

## Irrelevante Umgebung



- Speiseplan der Mensa – hat nichts mit Terminen bei Lehrenden zu tun.
- Ausleihe in der Bibliothek – läuft über ein eigenes System, das der Terminplaner nicht braucht.
