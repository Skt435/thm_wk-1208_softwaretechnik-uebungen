# Stakeholder und Systemkontext — Terminplaner für die THM


## Stakeholder

| Stakeholder | Worauf hat er Einfluss? |
|---|---|
| Professoren | Vergabe von Terminen |
| Kommollitonen | Belegung von Terminen |
| Mitarbeiter der THM (Bürokräfte) | Übersicht d. Systems |
| IT-Abteilung | Verantwortlich für die spätere Wartung d. Systems |
| Interne Revision | Verantwortlich für die Einnahmen und Ausgaben |
| Externes Entwicklerteam | Zuständig für die Implementierung und Integration |
| Server | Betreibt das System im späteren Ablauf |
| SOLL-Zustand des derzeitigen Rest-Systems | Spätere Integration, Aussehen, Framework |

## Systemkontext



| Aspekt | Art | Warum gehört er zum Kontext? |
|---|---|---|
| THM-Konto | System im Betrieb | Autorisierung und Authentizität muss gewährleistet sein |
| Dokument | System im Betrieb | Gängiges Kalenderdateiformat sollte vorhanden sein |
| UI | System im Betrieb | Das Aussehen des Interfaces sollte dem Rest des THM Systems ähneln|
| UX | Prozesse | Die Bedienung des Systems sollte eindeutig und leicht verständlich sein |
| Bedienung | Person | Sekretariatsmitarbeiter sollten das System mit ihren eigenen Autorisierungen bedienen können |
| Bedienung | Person | Professoren sollten das System mit ihren eigenen Autorisierungen bedienen können |
| Bedienung | Person | Kommollitonen sollten das System mit ihren eigenen Autorisierungen bedienen können |

## Irrelevante Umgebung

Mensa-Angebot und Öffnungszeiten der Cafeterien — reine Verpflegungsinfrastruktur; sie beeinflussen weder Terminfindung noch Verfügbarkeit von Räumen oder Personen.
Semesterbeitrag und Sozialausgaben (z. B. Semesterticket)  — administrativer/studenten­finanzieller Aspekt ohne Bezug zur Terminvergabe; für das System sind nur Kalender-, Raum- und Teilnehmerdaten relevant.
