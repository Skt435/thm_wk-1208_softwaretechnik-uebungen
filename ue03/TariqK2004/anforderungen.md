# Eigene Anforderungen

| Nr. | Stakeholder | Art | Anforderung |
| :--- | :--- | :--- | :--- |
| 1 | Studierende | FA | Studierende können ihre gebuchten Termine auf einem Platz sehen. |
| 2 | Hochschul-IT | QA | Die Daten werden verschlüsselt. |
| 3 | Studierende | FA | Das System schickt automatisch eine Erinnerung, wenn der Termin in 2 Stunden ansteht. |
| 4 | Professoren | FA | Professoren können Termine annehmen oder ablehnen. |
| 5 | System | FA | Ein Termin kann nicht doppelt gebucht werden. |
| 6 | System | QA | Wenn das Internet nicht mehr verfügbar ist und es bei einer Buchung zu einer Störung des Internets kommt, so wird der Termin gespeichert bzw. wird beim erneuten Login angezeigt und der Buchende kann seine Buchung fortführen. |
| 7 | Sekretariat | QA | Die Website ist relativ benutzerfreundlich aufgebaut, sodass das Sekretariat keine Schulung benötigt. |
| 8 | Lehrende | FA | Lehrende können ihre Sprechstundenzeiten selbst festlegen. |

## Warum hat das niemand gesagt?
Die Anforderung, dass ein Termin nicht doppelt gebucht werden kann, ist eine implizite Anforderung. Es ist für alle Beteiligten selbstverständlich, dass ein Platz nur einmal vergeben werden kann. Aus diesem Grund wurde es im Gespräch nicht explizit erwähnt.
